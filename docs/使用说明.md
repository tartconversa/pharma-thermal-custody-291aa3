# 冷链温控经历仓使用说明

本仓在原有合成资料检查器（`sourcepack`）之上，新增 `coldchain` 包：把本地合成的
交接单、装箱变化和仪器文件整理成质量复核与承运方都能核对的事实。**仓内只陈述
温控经历与证据缺口，不判定疗效，也不替代药品放行审批。**

## 1. 架构与口径落点

| 需求 | 实现 |
| --- | --- |
| 原始文件及接收情况持久保存 | 内容寻址归档 `raw_files/<sha256>.csv` + `ingest_batches`/`ingest_files`/`raw_rows`（append-only，同键整行修订保留全部历史） |
| 一次查询属于同一版 | 所有事实/集市带 `version_id` 不可变快照；查询走只读事务快照 |
| 复核引用可时间旅行 | `review_refs` 钉版，`review show` 同时给“当时事实/缺口”和“当前解释” |
| 新文件只影响有关系的货物 | `_affected_flows` 按回执/装载/仪器反查支流，局部重建；规则/批次/支流结构变化才全量 |
| 交接四态 | `closed` / `sent_only` / `received_only` / `quantity_mismatch`，相符量与争议量分列 |
| 重新装箱不产生新货物 | 根流窗口止于 `split_at`、子流起于 `split_at`，左右不重叠；可用量只计叶子支流 |
| 仪器只在装载时段作证 | 读数覆盖被装载区间截断；仪器移走后为 `no_load`，子流不继承未声明装载 |
| 末读不延长、无读数不合格 | 读数仅覆盖 `coverage_minutes`；空档为 `no_reading`，不无限延伸到下次交接 |
| 多仪器矛盾可查范围 | 判定矛盾记 `conflict`，`fact_conflicts` 给出冲突时间范围与两台仪器明细 |
| 重叠超限不翻倍 | 先在区间层对仪器取并集判定，再按物理时间累计，盒·秒不会乘仪器数 |
| 质量与责任同一份区间事实 | `fact_temp_intervals` 是唯一事实源；质量沿支流、责任按已确认接管区间相交得出 |
| 未知可追三类来源 | `unknown_reason`：`no_handoff`（没交接/在途）、`no_load`（没装载）、`no_reading`（没读数）、`no_rule`（无适用规则） |
| 补正联动重建 | 补正改接管时间→重建受影响支流的区间、可用量、双方集市；与拆分矛盾则 `pending_review` 待核，不偷移拆分 |
| 重复/中断/拆包相遇 | SHA256 去重不增事实；批次事务回滚后重跑幂等；拆分支流数量守恒、不继承未知经历 |

### 状态语义

- `normal` 正常 / `excursion` 超限 / `conflict` 多仪器判定矛盾 / `unknown` 证据不足。
- **未知或冲突都不能宣称正常**；可用量只统计窗口内全程 `normal` 的叶子支流盒数。
- 责任区段只包含**已确认接管**的时间（有 holder）；在途空档（holder 为空）不属于任何承运方；
  缺 receive 的尾部标 `end_pending`（责任终点待核）。

## 2. 目录

```
coldchain/
  schema.py     DuckDB 表结构（原始留存、版本、事实、集市、复核引用）
  times.py      时区(+08:00)、华氏摄氏、跨午夜切分
  engine.py     纯口径引擎（不碰数据库，可独立单测）
  warehouse.py  入仓、版本化重建、查询与复核 API
  cli.py        命令行入口
tests/
  test_engine.py     口径规则单测
  test_warehouse.py  入仓/版本/补正/故障恢复集成测试
run_tests.py         隔离模式测试入口
```

## 3. 环境与测试

```bash
python3 -m pip install -r requirements.txt
python3 -I run_tests.py                      # 全部 34 个测试
python3 -m compileall -q coldchain tests     # 语法构建
```

`-I` 为隔离模式：忽略环境变量与当前目录，避免资料目录中被植入的同名模块
（如 `json.py`）被解释器加载。原资料检查器仍可用：`python3 -m sourcepack`。

## 4. 实际可运行的入仓、补正与查询

资料包 = 一个目录，内含若干 `<表名>.csv`（表名与 `data/` 下一致）。每个资料包
独立目录、通过路径传入，脚本不放在资料目录内。

```bash
DB=warehouse/cc.duckdb

# 0) 初始化
python3 -I coldchain/cli.py --db $DB init

# 1) 基础入仓（不含补正），给出本次接收时刻
mkdir -p packs/base && cp data/{lots,flows,handoffs,logger_loads,readings,temperature_rules}.csv packs/base/
python3 -I coldchain/cli.py --db $DB ingest \
  --pack packs/base --received-at 2026-10-17T18:00:00+08:00 --note 基础资料

# 2) 后续单独接收补正（人工补正接管时间）
mkdir -p packs/correction && cp data/time_corrections.csv packs/correction/
python3 -I coldchain/cli.py --db $DB ingest \
  --pack packs/correction --received-at 2026-10-18T08:00:00+08:00 --note H4接管补正
```

### 查询（质量、责任、缺口、冲突、跨午夜、可用量）

```bash
# 交接四态与数量争议
python3 -I coldchain/cli.py --db $DB query handoffs
# 某支流完整温控区间（含每台仪器证据 evidence_json）
python3 -I coldchain/cli.py --db $DB query intervals --flow F1A
# 只看未知，并区分没交接/没装载/没读数/无规则
python3 -I coldchain/cli.py --db $DB query gaps --flow F1A
# 多仪器冲突范围
python3 -I coldchain/cli.py --db $DB query conflicts
# 质量口径：按批（盒·秒）、按支流（单盒秒 + 盒·秒）
python3 -I coldchain/cli.py --db $DB query quality-lot
python3 -I coldchain/cli.py --db $DB query quality-flow
# 承运方责任口径（同一区间事实，仅已确认接管段）
python3 -I coldchain/cli.py --db $DB query carrier
python3 -I coldchain/cli.py --db $DB query responsibility --party air
# 跨午夜日集市（按 +08:00 切日）
python3 -I coldchain/cli.py --db $DB query daily-quality --day 2026-10-16
python3 -I coldchain/cli.py --db $DB query daily-carrier --day 2026-10-17
# 当前可用量（证据完整且无冲突未知；不替代放行）
python3 -I coldchain/cli.py --db $DB query available
# 任意查询加 --version N 读取历史版本
python3 -I coldchain/cli.py --db $DB query quality-flow --flow F1A --version 1
# 加 --json 输出机器可读 JSON（--json 与 --db 同为全局参数，须放在子命令前）
python3 -I coldchain/cli.py --db $DB --json query carrier```

### 复核引用：当前解释 vs 当时所用内容

```bash
# 质量人员保存对某支流/批/承运方/交接的复核引用（钉住当前版本）
python3 -I coldchain/cli.py --db $DB review save --subject-type flow --subject-id F1A --note 首次复核
# 之后无论入了多少补正，都能同时读到钉版事实与当前版本解释
python3 -I coldchain/cli.py --db $DB review show --ref R-xxxxxxxxxx
python3 -I coldchain/cli.py --db $DB review list
```

### 接收审计与版本

```bash
python3 -I coldchain/cli.py --db $DB versions   # 版本谱系、每次受影响支流
python3 -I coldchain/cli.py --db $DB files      # 每个文件的摘要、行数、applied/duplicate
```

## 5. 关键边界行为

- **重复文件**：相同 SHA256 标记 `duplicate`，接收历史保留，但不新增原始行、不产生新版本。
- **中途停止**：`ingest --fail-after-files N` 可模拟崩溃；整批事务回滚，重跑同一包幂等，
  数量与区间不多算（集成测试 `test_crash_resume_no_double_count` 覆盖）。
- **同键修订**：新文件同业务键视为整行修订，旧行保留于 `raw_rows`，生效行取接收次序最后一条。
- **待核补正**：补正时点与拆分实物时点矛盾时置 `pending_review`，沿用原时点并记录原因，
  不自动移动拆分；补正不改变仪器实际装载，产生的空档如实呈现为未知。
- **数量拆分**：子流盒数之和等于根流；未拆出/未声明装载的支流只产生 `no_load` 未知，
  不会继承另一支流的正常或超限经历。

## 6. 编程接口

```python
from coldchain.warehouse import Warehouse

with Warehouse("warehouse/cc.duckdb") as wh:
    wh.ingest_pack("packs/base", "2026-10-17T18:00:00+08:00", note="基础资料")
    wh.ingest_pack("packs/correction", "2026-10-18T08:00:00+08:00")
    wh.query_gaps("F1A")                       # 未知及来源
    wh.query_conflicts()                       # 冲突范围
    wh.query_quality_lot()                     # 批次盒·秒
    wh.query_carrier(party="air")              # 承运方责任
    ref = wh.save_review_ref("flow", "F1A")    # 钉版
    wh.review_snapshot(ref)                    # 当时 + 当前
```
